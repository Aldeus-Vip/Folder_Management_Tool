# FolderManager(フォルダ整理・5S支援ツール)

大規模ファイルサーバーのフォルダ構成を **SQLite(.db)** に取り込み、ブラウザ画面で閲覧・分析・整理計画の記録を行う Windows 用ツールです。
Excel では扱いきれない規模(数十万〜100万行)でも軽快に動作します。

- インストール不要の **単一exe**(Python・Office 不要)
- 起動するとブラウザで画面が開きます(PC内だけで動作し、外部には通信しません)

## できること

| 分類 | 機能 |
|---|---|
| 取込 | FolderTreeExporter の Excel(.xlsx)を DB へ変換 / フォルダを直接スキャン(並列読み込み) |
| 統合 | 複数のDBを **フルパス基準で1つのツリーに統合**(重複パスは優先順で採用、注記も引継ぎ) |
| 表示 | **ツリー**(Excel風・罫線付き・サイズゲージ) / **エクスプローラー**(左フォルダツリー+右一覧) / **検索・リスト** / ダークモード |
| 分析 | サマリー(5Sチェック) / 重複候補 / 拡張子別 / 更新年数・階層の分布 / 容量の大きいフォルダ |
| 編集 | 各項目に **アクション**(残す・要確認・削除・アーカイブ・移動・名前変更)・担当・メモを記録 |
| 出力 | 検索結果・アクション一覧の CSV / アクションを実行する PowerShell スクリプト(既定はドライラン) |

## 使い方

1. `FolderManager.exe` をダブルクリック → ブラウザが開きます(黒いウィンドウを閉じると終了)。
2. ホーム画面で次のどれかを実行します。
   - **① Excelを取り込む**: FolderTreeExporter の出力ファイルを指定
   - **② フォルダをスキャンする**: 対象フォルダを指定(ネットワークドライブは「同時読み込み数」を増やすと速くなる場合があります)
   - **③ 保存済みのDBを開く**
   - **④ 複数のDBを統合する**: 部署別・ドライブ別に作ったDBをまとめて1つのDBにします
3. DB は exe と同じ場所の `projects` フォルダに保存されます。次回からは③で開けます。

### 画面の操作

- 行をクリック → 右パネルに詳細。アクション・担当・メモを記録できます
- `Ctrl` / `Shift` + クリックで複数選択、キー `1`〜`6` でアクション設定、`0` で解除
- ツリー: `←` `→` で開閉、「選択フォルダを N階層 展開」で一括展開、フルパス貼り付けで移動
- ツリーの「サイズゲージ」: 各行のサイズが **親フォルダに占める割合** / **全体に占める割合** をバーと%で表示(切替・非表示可)
- 画面右上のボタンでテーマを切替(自動 / ライト / ダーク)。「自動」はWindowsの設定に従います

### DBの統合(マージ)

- 統合元のDBは変更せず、新しいDBを作ります
- ルート: 全DBに共通する親フォルダ。共通部分が無い場合(別サーバー・別ドライブ)は「(統合ルート)」の下に各DBのルートを並べます
- 同じパスが複数のDBにある場合: 「データ取得日時が新しいDB」または「一覧の上にあるDB」を優先して採用します
- アクション・担当・メモも同じ優先順で引き継ぎます
- 検索・リスト: 名前・拡張子・警告種別・サイズ・更新日・アクションで絞り込み。結果すべてに「一括設定」も可能

## 5S チェック(サマリー画面)

| 5S | チェック内容 |
|---|---|
| 整理(要らない物) | 更新から一定年数以上 / 重複候補(同名・同サイズ) / 一時・システムファイル(`~$*`, `Thumbs.db` 等) / 空フォルダ |
| 整頓(探しやすさ) | コピー的な名称(「- コピー」「(1)」「新しいフォルダー」) / 版管理的な名称(旧・old・_v2・最新 等) / 中身がフォルダ1つだけ / 階層が深い / 直下の項目が多すぎる |
| 清掃・清潔(移行・運用) | SharePoint 禁止文字 / 末尾が「.」かスペース / 予約語 / パス長 / アクセス不可 |

閾値(古いファイルの年数・パス長など)はサマリー画面の「設定」で変更できます。

## 整理の進め方(例)

1. サマリーで全体像と問題の多い箇所を把握する
2. 5Sチェックの各項目から一覧を開き、アクション・担当を記録する
3. 「アクション計画」で担当別に CSV を出力し、各部署に確認を依頼する
4. 確定したら PowerShell スクリプトを出力 → まずドライランで確認 → `-Execute` で実行
5. 再スキャンし、「別DBから注記を引継ぐ」で前回の記録を引き継いで続きを行う

## 注意事項

- Excel 取込のサイズは Excel の KB 値(小数1桁)からの換算値です。正確な値が必要な場合はスキャンを使ってください。
- 重複候補は「ファイル名+サイズ」による簡易判定です。「重複候補」画面の「内容を比較」で SHA-256 による確認ができます(このPCから実ファイルにアクセスできる場合)。
- 生成される PowerShell スクリプトの「削除」は完全削除です(ごみ箱に入りません)。不安なものは「アーカイブ」で退避する運用を推奨します。
- 目安: 約77万行の Excel 取込で 30秒程度・メモリ約1GB・DB約300MB。

## 開発者向け

```
go test ./...                                    # テスト
FM_BIG=1 go test ./internal/ingest -run TestBigImport -v   # 約77万行の性能確認
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/FolderManager.exe ./cmd/foldermanager
```

| パス | 内容 |
|---|---|
| `cmd/foldermanager` | 起動処理(ローカルHTTPサーバー起動・ブラウザ表示) |
| `internal/xlsx` | 巨大 xlsx のストリーミング読み込み |
| `internal/ingest` | Excel 取込・フォルダスキャン |
| `internal/fsdb` | DB 構築(ツリー順採番・集計・警告判定)・検索・注記・出力 |
| `internal/server` | JSON API と画面(`web/`) |

GitHub Actions(`.github/workflows/build.yml`)で push ごとにテストと Windows 用 exe のビルドを行い、成果物(Artifacts)としてダウンロードできます。

起動オプション: `FolderManager.exe [-port 8765] [-projects フォルダ] [-no-browser] [開くDB]`(DBファイルを exe にドラッグ&ドロップしても開けます)。
