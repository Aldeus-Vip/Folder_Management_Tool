# ファイルサーバー整理・SharePoint移行 設計提案

## 1. 背景

### 1.1 対象規模(概算)
| 項目 | 値 |
|---|---|
| フォルダ数 | 約 295,000 |
| ファイル数 | 約 1,985,000 |
| 合計サイズ | 約 3.2 TB |
| 最大階層 | 23 |

### 1.2 移行計画
1. **初動**:IT部門が、ファイルサーバー(`Q:\`)の約半分を SharePoint へそのまま移行する
   - 移行範囲は**拡張子**で決まっている(移行済み/未移行は拡張子で判別できる)
2. **後半**:移行済み分と未移行分の両方を対象に、削除要否の判断と構成変更を行う
3. 未移行分を SharePoint へ移行し、ファイルサーバーの利用を終了する

### 1.3 本ツールの役割
- フォルダ・ファイルの削除要否と移動先(新構成)を判断し、作業内容を出力する
- 現状は、`Q:\` を対象に `Remove-Item` / `Move-Item` を1件ずつ書き込んだ PowerShell スクリプト(.ps1)を直接出力している

---

## 2. 現行方式(.ps1 直接出力)の課題

| # | 課題 | 内容 |
|---|---|---|
| 1 | 移行済み分を操作できない | 移行後は `Q:\...` が SharePoint の URL に変わるため、ファイルシステム操作では届かない |
| 2 | OneDrive同期経由は不可 | 約200万ファイルは、同期クライアントの推奨上限(約30万)を大きく超える |
| 3 | SharePoint上の移動に不向き | 同期フォルダ上の移動は「削除+再アップロード」になりやすく、バージョン履歴・作成者などのメタデータを失う |
| 4 | レビューしにくい | 判断内容がコードに埋め込まれており、承認者が確認・修正しにくい |
| 5 | 判断と実行が一体 | 判断を見直すたびに、スクリプトの再生成とレビューが必要 |
| 6 | ドライブ間移動の制約 | Windows PowerShell 5.1 では、`Move-Item` で別ドライブ(Q: → D:)へフォルダを移動するとエラーになる |
| 7 | 完全削除 | `Remove-Item` はごみ箱に入らず、復元できない |

---

## 3. 提案:「判断」と「実行」を分離する

### 3.1 全体構成
```
本ツール(判断)
   ↓ 出力
作業指示CSV(正本。レビュー・承認はここで行う)
   ↓ 所在(Location)ごとに振り分け
 ├ [SharePoint 移行済み分]  → ① PnP PowerShell(サーバー側で移動・削除)
 ├ [ファイルサーバー 削除]   → ② PowerShell(現行スクリプトの実行部を流用)
 └ [ファイルサーバー 移行]   → ③ SPMT で新構成へ直接移行
```

### 3.2 設計方針
- **出力の正本は CSV**:実行は「固定の汎用スクリプトが CSV を読み込む」形にする(5章)
- **移動先は相対パスで保持**:ルート(`D:\整理後` / SharePoint の URL)に依存しない
- **判断はフォルダ単位を基本**:Excel の行数上限(約104万行)を超えないようにし、レビュー負担を減らす
- **実行結果は CSV に書き戻す**:監査証跡として残す

## 4. 作業指示CSV 仕様(案)

### 4.1 列定義
| 列名 | 必須 | 例 | 説明 |
|---|---|---|---|
| `Id` | ○ | `000123` | 一意のID |
| `SourcePath` | ○ | `Q:\100_営業部\010_管理職` | 判断時点の元パス(`Q:\` 基準) |
| `ItemType` | ○ | `Folder` / `File` | 対象の種別 |
| `Action` | ○ | `Delete` / `Move` / `Keep` | 操作 |
| `TargetRelPath` | Move時 | `100_営業部\010_管理職` | 新構成ルートからの相対パス |
| `Location` | ○ | `SharePoint` / `FileServer` / `Both` | 実行時点の所在(4.3章で判定) |
| `Reason` | ○ | `ショートカット` / `Thumbs.db` / `重複` | 判断理由 |
| `DecidedBy` | ○ | (氏名) | 判断者 |
| `Approval` | ○ | `Pending` / `Approved` / `Rejected` | 承認状態。実行対象は `Approved` のみ |
| `SizeBytes` | - | `1048576` | 影響量の確認用 |
| `LastModified` | - | `2017-04-01T10:00:00` | 判断材料 |
| `Result` | - | `OK` / `ERROR: ...` / `NOTFOUND` / `DRYRUN` | 実行結果(書き戻し) |
| `ExecutedAt` | - | `2026-11-01T09:00:00` | 実行日時(書き戻し) |

### 4.2 ルール
- 文字コード:UTF-8(BOM付き。Excel で文字化けしないため)
- 親フォルダに `Move` / `Delete` がある場合、配下の行は「子→親」の順で実行する
- 親を `Delete` する場合、配下の個別行は不要(生成時に省略してよい)
- 新構成のフォルダ一覧は `target_structure.csv` として分離する(列:`TargetRelPath`)

### 4.3 所在(Location)の判定
初動移行の範囲は拡張子で決まっているため、**拡張子で一次判定 → 移行ログで補正**の2段階で判定する。

| 対象 | 判定 |
|---|---|
| ファイル(拡張子が移行対象リストに含まれる) | `SharePoint` |
| ファイル(上記以外) | `FileServer` |
| ファイル(移行ログで失敗・スキップ) | `FileServer`(補正) |
| フォルダ | `Both`(中身が両方に分かれるため) |

#### 拡張子だけでは誤判定するケース
- 移行に失敗したファイル(パス長超過、使用できない文字、ロック中など)
- 拡張子の大文字・小文字(`.XLSX` / `.xlsx`)→ 判定は大文字・小文字を区別しない
- 拡張子なし・二重拡張子(`README`、`backup.xlsx.old` など)
- 初動移行の後に `Q:\` 側で追加・更新されたファイル

実行時に見つからない対象は `NOTFOUND` として記録され、最後の安全網になる。

#### `Both`(フォルダ)の扱い
フォルダ行は、変換時に両方の工程へ振り分ける。

| フォルダの判断 | ① SharePoint 側 | ②③ ファイルサーバー側 |
|---|---|---|
| `Move` | 移行済み分を新構成へ移動 | 未移行分を新構成へ直接移行(③) |
| `Delete` | 移行済み分を削除 | 未移行分を削除(②) |

## 5. 実行物の構成

### 5.1 工程ごとの実行物
| 工程 | 実行物 | 使う仕組み | 入力 | 実行環境 |
|---|---|---|---|---|
| ① SharePoint 構成変更・削除 | .ps1 | **PnP PowerShell** モジュール | 作業指示CSV(SharePoint / Both)+ パス対応表 | **PowerShell 7**(`pwsh`) |
| ② ファイルサーバー 削除 | .ps1 | 標準コマンド | 作業指示CSV(FileServer / Both の Delete) | PowerShell 7 推奨(5.1 でも可) |
| ③ ファイルサーバー → SharePoint 移行 | .ps1 または SPMT 画面 | **SPMT** の PowerShell モジュール | SPMT 用の一括移行CSV | **Windows PowerShell 5.1**(`powershell`) |

### 5.2 方式:「汎用スクリプト + CSV」
| 方式 | 内容 | 評価 |
|---|---|---|
| 現行:生成型 | 判断結果を埋め込んだ .ps1 を毎回出力 | 毎回中身が変わるため、スクリプト自体のレビューが必要 |
| **推奨:汎用型** | **固定の .ps1 が CSV を読み込んで実行** | スクリプトは一度テストすれば済み、レビューは CSV だけでよい |

### 5.3 リポジトリ構成(案)
```
repo/
 ├ docs/
 │   └ migration-reorg-proposal.md   ← 本書
 ├ scripts/
 │   ├ 1_sharepoint_reorg.ps1         ← CSV を読んで PnP で移動・削除
 │   ├ 2_fileserver_delete.ps1        ← CSV を読んで削除(現行の実行部を流用)
 │   ├ 3_migrate_spmt.ps1             ← SPMT 用 CSV を読んで移行
 │   └ common.ps1                     ← ドライラン・ログ・結果書き戻しの共通処理
 ├ tools/
 │   ├ resolve_location.ps1           ← 拡張子+移行ログで Location を判定
 │   ├ map_path.ps1                   ← パス対応表で Q:\ → SharePoint URL に変換
 │   └ convert_to_spmt_csv.ps1        ← 作業指示CSV → SPMT 用 CSV に変換
 ├ launchers/                          ← 任意
 │   ├ run_1.bat                      ← pwsh で起動
 │   ├ run_2.bat
 │   └ run_3.bat                      ← powershell(5.1)で起動
 └ data/
     ├ work_order.csv                 ← 本ツールの出力(正本)
     ├ target_structure.csv
     ├ migrated_extensions.txt        ← 移行対象の拡張子リスト(IT から入手)
     └ path_map.csv                   ← パス対応表(IT から入手)
```

### 5.4 共通仕様(3本とも)
- `-Execute` を付けない限り変更しない(ドライラン)
- 実行ログを CSV に出力し、作業指示CSV の `Result` / `ExecutedAt` に書き戻す
- 対象が存在しない場合は `NOTFOUND`、例外は `ERROR: <メッセージ>` として記録し、処理を継続する

### 5.5 バッチファイル(.bat)の位置づけ
- **必須ではない**。ダブルクリックで起動する入口としてのみ使う
  - 実行ポリシーの指定(`-ExecutionPolicy Bypass`)を省略できる
  - ①は `pwsh`、③は `powershell` と、正しいバージョンで起動できる
- 処理そのものは .bat に書かず、.ps1 に任せる

### 5.6 ②の実装上の注意
- ドライブ間のフォルダ移動は PowerShell 7 または robocopy `/MOVE` を使う
- 削除は「`_削除予定` フォルダへ移動 → 一定期間後に削除」の2段階を選べるようにする

## 6. 実行手順

| 順 | 工程 | 対象 | ツール | 備考 |
|---|---|---|---|---|
| 0 | 判断・承認 | 全体 | 本ツール → CSV | Location 判定、パス対応表による URL 変換 |
| 0' | ドライラン | 全体 | ①②③ を `-Execute` なしで実行 | 結果を承認・依頼資料に添付 |
| 1 | 新構成フォルダ作成 | SharePoint | PnP PowerShell | `target_structure.csv` から作成 |
| 1 | 構成変更・削除 | SharePoint(移行済み分) | PnP PowerShell | 削除はごみ箱(既定93日)に入る |
| 2 | 削除 | ファイルサーバー(未移行分) | PowerShell | 移行前に削除し、移行量を減らす |
| 3 | 移行 | ファイルサーバー → SharePoint | SPMT | `Move` 行を SPMT 用 CSV に変換し、**新構成へ直接移行** |
| 4 | 検証 | 全体 | 本ツール | 件数・サイズ・NOTFOUND・ERROR の確認 |

- 工程 1 と 2 は互いに独立しており、並行してよい
- 工程 3 は、工程 1(移行先フォルダの作成)と工程 2(削除)の**両方の完了後**に行う
- 工程 3 の前に、`Q:\` の未移行分を**読み取り専用**にし、作業中の更新を止める(移行漏れ防止)

## 7. 権限と役割分担

### 7.1 工程ごとに必要な権限
| 工程 | 必要な権限 | 備考 |
|---|---|---|
| ① | SharePoint サイトの編集権限 + **Entra ID のアプリ登録** | PnP PowerShell の認証に必要。登録は IT 部門の作業 |
| ② | 対象フォルダの**削除権限(NTFS)** | エクスプローラーでの削除と同じ権限で実行できる |
| ③ | ファイルサーバーの読み取り + SharePoint の編集権限 | SPMT のインストールが必要 |

### 7.2 ②を業務側で実行する場合の注意
- 全フォルダに削除権限があるとは限らない(管理職フォルダなどは `ERROR` になる)
- 使用中(ロック中)のファイルは削除できない
- 削除はごみ箱に入らないため、**事前に IT のバックアップ(スナップショット)を確認**する
- 権限があっても、共有サーバーの大量削除は事前の組織的な合意が必要

### 7.3 役割分担(案)
**判断と準備は業務側、本番実行は IT 部門**とする。

| 担当 | 作業 |
|---|---|
| 業務側 | 作業指示CSV の作成・承認取得、スクリプト作成、**ドライラン結果の提出** |
| IT 部門 | アプリ登録、バックアップ確保、①②③の本番実行 |

- ドライラン結果(何が・何件・どこへ)を添えて依頼し、IT は「内容の確認」と「実行」に集中できるようにする
- 選択肢:②のみ、IT のバックアップ確認後に業務側で実行する

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| 誤削除 | 承認済みのみ実行。ドライラン必須。2段階削除(ファイルサーバー)/ごみ箱(SharePoint)。事前バックアップ確認 |
| Location の誤判定 | 拡張子+移行ログの2段階判定。実行時の `NOTFOUND` で検出 |
| パス長超過 | SharePoint の上限(URL デコード後 400 文字)を判断時にチェックする |
| 使用できない文字 | `" * : < > ? / \ |` などを判断時に検出し、名称変更を作業指示に含める |
| 移行中の更新 | 工程 3 の前に読み取り専用化。必要なら差分移行 |
| 権限不足 | ドライランで `ERROR` を事前に洗い出す。本番は IT 部門が実行 |
| 権限の未移行 | ファイルサーバーの NTFS 権限は移行されない前提で、SharePoint 側の権限設計を別途行う |

## 11. レビュー結果と実装状況(FolderManager 側)

### 11.1 本書への補足・修正点

| # | 項目 | 内容 | 対応 |
|---|---|---|---|
| 1 | 初動移行は「コピー」か「移動」か | IT の初動移行がコピー(`Q:\` 側に残る・参照専用)の場合、移行済み拡張子のファイルは `Q:\` にも残る。③ SPMT でフォルダを移行すると **二重に移行される** ため、SPMT の「拡張子で除外」設定で移行済み拡張子を除く必要がある。② の削除も `Q:\` 側だけでは足りない(SharePoint 側は ① で削除) | IT に確認(8章に追加) |
| 2 | 4.2「親を Delete する場合、配下の個別行は不要」 | 配下の **Delete** は省略してよいが、配下の **Move**(削除フォルダから救出する項目)は残し、親の削除より先に実行する必要がある。配下に **保留** がある場合、親を削除すると保留の項目も消える | 作業指示CSVで対応済み(配下の Move は残す・Note で警告) |
| 3 | ③ SPMT と配下の例外 | SPMT はフォルダ単位で丸ごと移行するため、移動するフォルダの配下に別の Move・Hold があると、親と一緒にも移行されてしまう(二重移行・保留の無視)。作業指示CSVからの変換だけではツリー構造が分からず除外できない | 本ツールで「例外を除いた SPMT タスク(残りのサブフォルダ・ファイル単位に分割)」を出力するのが確実(次の実装候補) |
| 4 | ファイル単位の Move・名前変更 | SPMT のタスクはフォルダ単位が基本。ファイル単位の移動先・名前変更は、③ で親フォルダごと移行した後に ① と同じ方法(PnP)で SharePoint 上で移動する方が確実 | 工程の順序に反映を推奨(③ → ①') |
| 5 | スキャン後の更新 | 判断はスキャン時点のデータに基づくため、その後に追加・更新されたファイルが「削除」フォルダに入っていると一緒に消える | 作業指示CSVに `ScannedAt` を追加。実行スクリプトで「ScannedAt より新しい項目を含む削除は `SKIPPED_NEWER` として止める」を推奨 |
| 6 | 未処理・保留の扱い | 作業指示CSVには判断済みの行だけが入る。未処理・保留のまま残った項目をサーバー終了時にどうするか(現状の構成で移行 / 移行しない)を決めておく必要がある | 運用ルールとして決定が必要 |
| 7 | SharePoint の禁止文字 | 現在の SharePoint Online は `#` `%` を使用可。本ツールの「禁止文字」警告は `#` `%` も含むため厳しめ。名前の先頭・末尾の空白、`.lock`、`_vti_`、`CON` などの予約名は不可 | 作業指示CSVの Note は SharePoint の禁止文字で判定 |
| 8 | 400文字の判定 | 上限はサイトURLを含むデコード後のフルパス。「⚙ オプション → 整理後のルートの実際の場所」に SharePoint の URL を設定すると、判断時・作業指示CSV(Note)で判定できる | 設定で対応 |
| 9 | 大量処理の制限 | PnP での大量操作は SharePoint の調整(HTTP 429)にかかる。共通処理に再試行(待機して再実行)を入れる。5,000件を超えるフォルダの列挙はページングが必要 | スクリプト実装時に対応 |

### 11.2 作業指示CSV(実装済み)

「アクション一覧」→「作業指示CSV出力…」で出力する。4章の仕様から次を変更・追加している。

| 列 | 内容 |
|---|---|
| `ExecOrder` | 実行順(子 → 親)。この順に実行すればよい |
| `Action` | `Move` / `Delete` / `Hold`(保留。実行しない)。未処理の項目は出力しない(`Keep` は使わない) |
| `Location` | ファイルは画面で入力した「初動移行の拡張子」で判定(大文字・小文字を区別しない)、フォルダは `Both`。移行ログによる補正は `resolve_location.ps1` で行う |
| `Reason` | メモ(無ければタグ) |
| `FileCount` / `SizeBytes` | その行の操作が及ぶファイル数・サイズ(配下で別の操作を設定した部分を除く) |
| `ScannedAt` | 判断の元になったスキャン日時 |
| `Due` / `Owner` | 期限 / 担当(部・課・担当・担当者) |
| `Note` | 配下の移動・保留、SharePoint の禁止文字、400文字超、スキャン時のアクセスエラーなどの注意 |

`target_structure.csv`(列: `TargetRelPath`, `Depth`, `Memo`)も同じ画面から出力する。親 → 子の順なので上から作成すればよい。

### 11.3 移行量の見積もり(実装済み)

前提: 初動移行は **コピー**(`Q:\\` に移行済みの分も残る)。移行済みの分は SharePoint 側が最新なので SharePoint 上で整理し、`Q:\\` にしか無い分だけを移行する。

| 工程 | 対象 | 方法 |
|---|---|---|
| Step1 | 移行済みの拡張子のファイル | SharePoint 上で新構成へ移動・削除(PnP) |
| Step2 | それ以外の拡張子のファイル | 新構成へ移行(量により SPMT / ブラウザ)。削除と判断した分は移行しないだけでよい |

「作業指示CSV出力…」の「📊 移行量を見積もる」で、Step1・Step2 のそれぞれについて、移動・削除・保留・未処理のファイル数・サイズを表示する。Step2 は移行が必要なファイルの分散(フォルダ数)、移行の単位の数、拡張子の内訳も表示し、SPMT が必要かの目安を示す(約77万項目で1秒未満)。

初動移行の範囲は、IT から受け取るリストの形に合わせて「移行した拡張子」「移行しなかった(除外した)拡張子」のどちらでも指定できる。Excel の表(種類名・見出しを含む)をそのまま貼り付けても拡張子の列だけを読み取る。拡張子とは別に、フォルダ単位で移行しなかった範囲(除外フォルダ)も指定できる。見積もりには「移行済みと判定した拡張子」の内訳も表示するので、判定が意図どおりか確認できる。
